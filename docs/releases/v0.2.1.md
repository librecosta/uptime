v0.2.1 adds private operational dashboards and more control over alert recovery.

- **Alert history:** Optional `/alerts` shows incidents and per-channel delivery details, including reminders and canceled retries, with UTC times and paginated browsing.
- **Process Monitor:** Optional `/monitor` provides Fiber Contrib Monitor's native process/system dashboard and HTTP statistics.
- **Access:** Both operational dashboards require Basic Auth. `auth.protect_uptime: false` can publish the Uptime page and status API while keeping operational data private.
- **Recovery and reminders:** Require 1–10 consecutive successes before recovery (default one). Optional reminders follow real failed probes, with a frozen interval and limit per incident.

All new features are **off by default** except the compatible one-success recovery policy. See the [example configuration](https://github.com/librecosta/uptime/blob/v0.2.1/configs/uptime.example.yaml).

Download your platform's archive and verify `SHA256SUMS` from [GitHub Releases](https://github.com/librecosta/uptime/releases/tag/v0.2.1), or use `ghcr.io/librecosta/uptime:v0.2.1` for Linux amd64/arm64. Native archives support Linux/macOS amd64/arm64 and Windows amd64.

**Before upgrading:** Stop all alert executors and back up monitoring and alert state together. bbolt alerts upgrade from Schema v1 to v2; Redis resumes its history-index migration before startup. Existing incidents keep reminders off unless they already have a frozen policy; `uptime.db` is unchanged. Do not downgrade in place; restore a complete pre-upgrade backup with the old binary instead.

New reminder configuration accepts `5m` through `720h` (30 days) and 1–10 reminders, or `0s`/`0` to disable. Earlier saved policies retain their original limits. `/alerts` is reserved, and enabled `/monitor` must not overlap `ui.path`.

Run one alert executor per database/Redis prefix. Notifications remain at least once with at most ten attempts and may repeat or arrive late during recovery. History is read-only; no ACK, manual resend or deletion is provided. In-process alerts cannot detect the monitor's complete process failure. Use HTTPS for remote Basic Auth access.
